## 工期口径（先读这条）
**L2–L4 的工期是估算值（分钟），只用于表达判据依赖与关键路径，不是验收时限。** 每个节点都标「工期 N（估）」，图注同样写明。实测只作参照、不折算成工期：p13 首次 `make docker-up` 构建约 8 分钟（page-13 实测）、p22 级考核抢 init 退出窗口约 3 秒（page-22 实测，是时间窗不是工期）、p14 `make stage3` 本机 33.94 秒 / p15 `make stage4` 约 38 秒（是运行耗时）。

## 怎么读节点（CPM 字段）
- **编号 + 活动名**：P10–P22 对应 page-10…page-22；G2 / G3 / G4 = 该级级考核（末页「拆一刀」）。
- **工期**：节点内「工期 N（估）」，单位分钟；它只影响 ES/EF/LS/LF。
- **ES / EF**：最早开始 / 最早完成（正推：EF = ES + 工期，ES 取紧前 EF 的最大值）。
- **LS / LF**：最晚开始 / 最晚完成（逆推：LS = LF − 工期，LF 取紧后 LS 的最小值，终点取总工期）。
- **浮动**：总浮动 = LS − ES = LF − EF；0 = 关键路径。橙色节点 / 箭头 = 关键路径；虚线 = 回流（不是 FS 依赖，不计入 CPM）。

## 关键路径结论

- **L2 换（80 分钟，估）**：P10 换真数据 → P12 换真执行器 → P13 换真部署 → G2；P11 换真契约与 P10 并行，**总浮动 5 分钟**，不进关键路径（真数据更长，执行器等两者）。
- **L3 审（110 分钟，估）**：P14 → P15 → P16 → P17 → G3 全串行、无浮动；P17 的虚线「回流」指回 P15，表示纠错失败 / 可重试时回生成重试（重试路径，不参与 CPM）。
- **L4 守（110 分钟，估）**：P18 → P19 → P20 → P21 → P22 → G4 全串行、无浮动；P22 是汇聚节点，前四项全部完成才能开始回归。

## 与 D44 的一致性

D44 把 L2–L4 定义成**横切系统**（换 / 审 / 守），不是「又一批零件」。所以这三张网络表达的是**判据依赖**（前一条判据绿了才能开始下一条），不是施工顺序或建筑层级；级与级之间用「起点 = 上一级终局（图外）」衔接，级内不再画 L1 的零件。节点仍是该级一页的核心动作 + 级考核；验证只作完成判据，不单独成节点。
