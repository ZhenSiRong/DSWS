## 工期口径（先读这条）

**L2–L5 的工期是估算值（分钟），只用于表达判据依赖与关键路径，不是验收时限。** 每个节点都标「工期 N（估）」，图注同样写明。实测只作参照、不折算成工期：p13 首次 `make docker-up` 构建约 8 分钟（page-13 实测）、p22 级考核抢 init 退出窗口约 3 秒（page-22 实测，是时间窗不是工期）、p14 `make stage3` 本机 33.94 秒 / p15 `make stage4` 约 38 秒（是运行耗时）。L5 新增的 P23 20 分钟 / G5 10 分钟是同一口径的估算值（没有实测依据，只表达"一页 + 一次拆一刀"）。

## 怎么读节点与箭头

- **节点**：编号 + 活动名 / 工期（估）/ ES EF LS LF（分钟）/ 完成判据。P10–P23 对应 page-10…page-23；G2–G5 = 该级级考核（末页「拆一刀」），画成菱形。**ES/EF** 正推（EF = ES + 工期，ES 取紧前 EF 最大值）；**LS/LF** 逆推（LS = LF − 工期，LF 取紧后 LS 最小值，终点取总工期）；**浮动** = LS − ES，0 = 关键路径。
- **箭头**：橙色 = 关键路径；实线 = 级内 FS；**虚线 = 级间 FS**（L2→L3→L4→L5 串行，**计入 CPM**）；点线 = 回流重试（P17⇢P15，**不计 CPM**）。
- **起点 = L1 交付**（A0–A9 全绿 + 建成证明海报；图外，L1 网络见旧图 `flow.mmd`）。**本图是判据依赖网，不是施工工期、不是城市图。**

## 关键路径结论

- **L2 换（80 分钟，估）**：P10 换真数据 → P12 换真执行器 → P13 换真部署 → G2；P11 换真契约与 P10 并行，**总浮动 5 分钟**，不进关键路径（真数据更长，执行器等两者）。
- **L3 审（110 分钟，估）**：P14 → P15 → P16 → P17 → G3 全串行、无浮动；P17⇢P15 点线是纠错失败 / 可重试时的重试路径。
- **L4 守（110 分钟，估）**：P18 → P19 → P20 → P21 → P22 → G4；P22 是汇聚节点（P18/P19/P20 三条汇聚边，前四项全部完成才能开始回归）。
- **L5 装（30 分钟，估）**：P23 装成熟前端（成熟版原版前端 `shopkeeper-agent` → nginx 8088，出 `41,099.5` 即 `41099.5`）→ G5；级考核 = 把前端换回第 9 页 17 行 HTML（补接线）仍出 `41099.5`；教学版 8080 只作脚手架对照。
- **合计 330 分钟 = 80 + 110 + 110 + 30**：级间靠 G2→P14、G3→P18、G4→P23 三条虚线串起来；不计级间时四级是四张互不相连的网（最大一段 110）。

## 与 D44 / D50 的关系

D44 把 L2–L4 定义成**横切系统**（换 / 审 / 守），不是「又一批零件」；D50 追加 L5「装」体验层 1 页（page-23），配比 10+4+4+5+1 = 24 页。所以这张合并图表达的是**判据依赖**（前一条判据绿了才能开始下一条），不是施工顺序或建筑层级：节点仍是该级一页的核心动作 + 级考核，验证只作完成判据、不单独成节点。级间在图上用里程碑虚线衔接（旧三张图各写「起点 = 上一级终局（图外）」，合并后变成真实边并计入 CPM）。
