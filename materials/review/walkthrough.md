## 附录 A：输出与页面不一致（硬证据）

- **A1（P9，环境向但手册无排查）**：首跑 `curl -i http://127.0.0.1:8081/` → `HTTP/1.1 403 Forbidden`，nginx error log：`open() "/usr/share/nginx/html/index.html" failed (13: Permission denied)`。原因：我创建文件为 0600（写文件工具 umask 077），nginx worker 非 root 读不了；`chmod 644` 后立即 200。普通编辑器存盘多为 644，但 umask 077 / sudo 创建会踩；页面“你应该看到”只写 41099.5，无 403 说明。
- **A2（P7）**：对账说 500 时“前面还有一段 pymysql 的报错”。实测日志顺序：`INFO: ... "POST /api/query HTTP/1.1" 500` 在前，`ERROR: Exception in ASGI application` + pymysql traceback 在后；且 `curl -s` 返回后 traceback 稍晚才落盘（第一次 `tail` 还看不到）。
- **A3（P0，声明偏差）**：第 3 条 `make install` 未执行（venv/node_modules 已存在）；其余四条输出与页面逐字一致。第 5 条三端口空闲与页面一致。
- **A4（P0 自己改）**：`3306` 确实“被占用”，但占用者是本机 Docker 容器 `dsws-trace-mysql-1`（127.0.0.1:3306），不是“本机自带的 MySQL”；结论（所以本课用 3307）成立，归因文字在本机不成立。
- **A5（P6 自己改，我的操作假象，非手册缺陷）**：同一秒内两次改 `"华东销售额"→"华南订单量"`，两次字符串等长，Python 复用未失效的 `.pyc`，输出仍是旧 `WHERE '华东'`/`SUM`；`rm -rf lab/__pycache__` 后正确输出 `COUNT(DISTINCT ...)`/`华南`。记此条避免把假象当手册问题。
- **A6（P9）**：“点完 0.6 秒左右页面上正停着 `recall_value`”：实测 150ms/条，约 450ms 是 `recall_value`，600ms 已是 `recall_metric`；文字略有出入，不影响“一条条到”的结论。
