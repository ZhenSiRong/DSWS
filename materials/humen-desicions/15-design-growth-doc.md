# 15 · 设计文档决策生长：范围、渐进稿版式与教学编撰（2026-11-27）

> 本文记录 2026-11-26 深夜一轮决策的完整逻辑：背景、备选、取舍、后果、何时可推翻。
> 对应 `DECISIONS.md` 的 **D56–D57**。触发方式：grill 定案（用户睡前拍板，余下由 agent 自主执行到无可挑剔）。
> 需求锚点：`prd.md`（设计文档≥30 页；NL2SQL / LangGraph 12 节点 10 步 / validate_sql+correct_sql 双保险 / React 19 + Tailwind 前端）。

## 背景（为什么现在要动）

- 3 份 A 类设计文档（security / contract / runtime）首版被用户判定「没有渐进式设计的思路，学生们没有看到一个好的设计是怎么长出来的」——只有"行业答案"感，没有生长过程。
- 工作流 `toolbox/workflows/design-doc-growth.md` v1 明文「不许编造时间线」，与用户新口径「**先编撰**，后面再让别的 agent 修订成自恰又不用修改源码/源配置的版本」直接冲突，必须裁决。
- 交付要求升级：今晚完成的不是 3 份增补，而是**整份设计文档**；且整个 worktree 要达到可交付直接标准。
- 人审预算为零（用户睡觉），需要人拍板的决策必须在睡前定完，其余由 agent 自主迭代。

## D56 设计文档范围与装配（锚定 prd）

**决定**：「完成整份设计文档」= A 类 **5 条链**渐进稿全部生产并同步配套文件——纠错 / 安全 / 契约 / 运行 + 新增**用户旅程设计**（旅程**从源码推导**：前端问数入口 → API → LangGraph 节点 → SQL → 结果，不凭空编）；**B/C 类一律不做、不入卷**；合入主 PDF 出完整 `design-doc.pdf`（≥30 页、不含 B/C 类页）→ `deliverables/design-doc/`，更新 MANIFEST/SHA256SUMS。**不止设计文档**：源码 1 套、开发手册 1 套同样要达到万无一失的可交付直接标准（对照 prd 三件套逐项验收）。**质量线（用户 2026-11-27 追加）**：终验前必须做一轮全面检查/修订，确保学生**愿学（有钩子、问题先行）、爱学（有故事、有成就感）、能学（台阶平、术语白话、能上手）**。

**备选**
| 方案 | 优点 | 否决原因 |
|---|---|---|
| A. 只收 3 份 A 类增补卷 | 最快 | 用户明确「不止三类，今晚的任务是完成整份设计文档」 |
| B. A/B/C 三类全部补齐 | 覆盖面最大 | 用户明确「B/C 不要了」 |
| C. A 类 5 链渐进稿 + 合入主 PDF ✅ | 对齐 prd 三件套，可直接交付 | — |

**决策逻辑**：prd 的验收对象是"一份 ≥30 页的设计文档"，不是零散增补；A 类图承载设计决策（教学价值所在），B/C 类是自动生成/附录，砍掉不伤主线，但**页数账必须≥30**，缺口用渐进稿与文字章节补足并在终审报告里报账。

**后果**：主 PDF 重建（不再只是增补卷）；「用户旅程设计」为新增 A 类链，图源、claim、证据一并新建；B/C 类页从主文档移除后需复核目录/页码。

**何时推翻**：评审明确要求 B/C 类图入卷；或用户旅程并入其他链更合理。

## D57 渐进稿版式与教学编撰口径

**决定**：

1. **版式**：渐进稿左页 = **2×2 四格、Z 字阅读 v1→v2→v3→v4**，每格「做法 + 被什么打脸 + 补上了什么」，v4 格标「当前」；右页保持终态设计 + 证据 + 可重跑命令。取代首版 v0–v3 纵排时间线。
2. **教学编撰**：放行编撰生长时间线。时间线是**教学重构**，不是 commit 历史或逐日日记；必须带**编撰声明**；claim/证据规则不变——终态设计必须由代码/契约/真跑证据锚定，证据缺口照标 `[未知]`，禁止"行业惯例"补空。
3. **叙事校对（reconciler）边界**：后续由其他 agent 把编撰叙事修订自恰，**只改叙事、不改源码/源配置**；叙事与源码冲突时以源码为准改叙事并留痕。

**备选**
| 方案 | 优点 | 否决原因 |
|---|---|---|
| A. 维持「不许编造时间线」绝对禁令 | 最严谨 | 无历史记录时永远写不出"怎么长出来"；用户已明确授权先编撰 |
| B. 编撰但不声明 | 叙事最顺 | 冒充真实历史，答辩一问即穿 |
| C. 编撰 + 编撰声明 + reconciler 只改叙事 ✅ | 教学性与诚实兼得 | — |

**决策逻辑**：教学文档的第一性是"学生看懂设计怎么长出来"，不是"史料保真"；但诚实性用声明兜底而不是用禁令兜底——声明让读者知道哪些段落是重构，锚定让结论可复核，reconciler 让叙事最终收敛到与源码自恰。

**后果**：`design-doc-growth.md` §3/§10 口径改写（本决定生效即取代原文"不许编造时间线"条款）；每份渐进稿固定带编撰声明段；reviewer 审查口径从"时间线真不真"改为"声明在不在、终态锚没锚、证据挂没挂"。

**何时推翻**：拿到真实设计史料（会议记录、issue 历史、commit 叙事）可替换对应编撰段落，并撤下该段的编撰声明。
