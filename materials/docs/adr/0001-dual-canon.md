# 双正典治理：md 管内容真相，重构版管呈现真相

**状态**：accepted（2026-11-23）

练本的内容真相只有一份——`tutorial/page-*.md`，六段结构、判据原句、命令与数字以它为准，`audit_book.py` 只审它；由它派生的 `tutorial/read/` 阅读版 HTML 是生成物，永不手改（手改必被下一次 `render_read.py` 覆盖）。但我们同时批准了一条**重构版（rebuild）实验轨**：从阅读版 HTML 出发，用 GrapesJS 点选组件、人为优化阅读体验，产物在 `tutorial/rebuild/`，**自身即正典**。这不是"两个互相覆盖的源"，而是把两种真相分开：md 决定"说什么"，重构版决定"怎么呈现"。代价是明确的——md 后续修改**不会自动流入**重构版，必须显式重移植，且每次重构页要记录派生基线（md 的 git 提交＋日期）。

## 被否决的选项

- **手改 md 派生的 HTML**：会被下一次 render 覆盖，制造"改了又丢"的漂移，否决。
- **只保留 md ＋CSS 调样式**：无法做组件化重构（步骤卡、callout、TOC、复制按钮），达不到用户要的阅读形态，否决。
- **在 md 之上做模板化的组件构建管线**（如 Astro/Eleventy）：内容仍单源，但它是"写代码产组件"，不是用户要的"点 UI 建组件"，暂不选；若 GrapesJS 试点失败可回退到此路。

## 后果

- 重构版与 md 之间存在**有意的漂移窗口**：内容更新后需人工重移植，`tutorial/rebuild/` 页面必须标注基线提交。
- `audit_book.py` 不覆盖 `tutorial/rebuild/`；该轨道的验收靠试点六条判据（内容对等 / 组件可用 / 正典不破 / 闸门不破 / 肉眼裁决 / 可重现）。
- 试点（p17 一页）未通过前，阅读入口保持 `tutorial/read/`，不得替换。
