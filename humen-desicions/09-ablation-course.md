## D20 教材重构：主线练本 + 原书降为参考书

**决定**：新写一本主线（9 页起步、可长到 30 页），原书 162 页**一个字不动**，降级为"参考书/查字典"。

**备选**
| 方案 | 优点 | 否决原因 |
|---|---|---|
| A. 在原书上删改 | 只交一份 | 162 页是链式结构，删一节垮三节；写坏了无法回退 |

## D21 九站构建切法（不是十二步，是九个里程碑）

**决定**：练本以 9 个"能跑的里程碑"组织，每页末尾系统必须**多出一个可验证的新行为**。

| 页 | 造什么 | 页末能看到 |
|---|---|---|
| 1 | 起库 + 建 `fact_order` | `SHOW TABLES` 有它 |
| 2 | 灌 115 行种子 + SELECT | `COUNT(*) = 115` |
| 3 | 最小 HTTP 服务 | `curl /health` → ok |
| 4 | `/api/query` 硬编码 | 固定 JSON |
| 5 | 抽关键词 | `["华北","销售额"]` |
| 6 | 查契约 + 拼 SQL | 打印那条 SELECT |
| 7 | 真执行 | **`41099.5`** |
| 8 | 改成 SSE | 12 条 progress 逐条冒 |
| 9 | 接原版界面（nginx 反代） | 浏览器出结果 |

**决策逻辑**：3 页版虽然"跑得通"，但**像部署不像构建**——`compose up -d` 是别人盖好房子你按开关。放宽到 9 页后，每页都有"自己垒出来的一块"，且前 8 页都不需要界面（用 curl 验证），天然教出"前端只是入口"。

**余地**：若第 8 页（SSE）写不完，把第 9 页（界面）降级为附录——**SSE 比界面更核心**（答辩要演流式）。

**何时推翻**：写到第 7 页时评估剩余时间。

## D22 教学法内核：猜 → 造 → 对账

**决定**：每一页固定四段：**一个预测问题 → 动手造 → "你应该看到"的判据 → 对账（你猜对了吗，差在哪）**。

**备选**：学→做→验（先讲后练）；装→跑→问→验。

**否决原因**：两者都是"先灌后练"，学生仍是被动。**"先猜"零成本，却把"照做"变成"理解"**——预测被打脸的那一刻才是学习发生的时刻（本项目的删 frontend 教学实验已验证：学生猜"系统坏了"，实际主干还活着）。

**后果**：每页必须有一个"错误预测也有价值"的问题；不能只出送分题。

## D23 单页预算（"精细"的可操作定义）

**决定**：每页硬上限——**1 个新代码段（≤40 行）+ ≤3 条命令 + 1 个"你应该看到" + 1 个"猜"的问题 + 1–3 行"必须自己改"的小任务**。

**决策逻辑**：精细 ≠ 命令写得多。检验标准是**每条命令都有对照物**——学生卡住时只需自问"我的输出和书上这行一样吗"。

**后果**：超过 40 行的页要拆；"必须自己改"是防抄的硬钩子。

## D27 worktree 隔离策略（"刀刃"）

**决定**：隔离切在 **代码 / 依赖 / 运行单元** 与 **数据** 之间——前三者每实验一份，**数据默认共享**。

**前提（契约）**：共享数据成立的条件是 ①全链路只读（`dw_reader` 仅 SELECT）②**谁都不跑 `init`**。要写数据（改种子/重建 meta/改 schema）时才必须独立一份。

**事实依据**（本仓库实测）
- worktree 隔离工作文件 + index + HEAD；**共享** `.git/objects` 与 `refs`（`.git/index` 与 `.git/worktrees/<wt>/index` 是两个文件）。
- 两套独立栈（主栈 / lab 栈）数据指纹完全一致：5 张表 checksum 相同、ES 76 docs、Qdrant 98/22。

**后果**：不复制存储；用命名空间（`REBUILD_META_DB` / `REBUILD_ES_INDEX` / collection 名）隔离需要改数据的情形。

**何时推翻**：实验要改数据本身（那时数据就是第二个因子）。

## D28 六格仪表盘（变量 × 仪器）

**决定**：对比实验前必须采集六格身份卡：

| 变量 | 声明 | 现场 | 身份 |
|---|---|---|---|
| 代码 | 分支/提交 | `git status` | commit sha |
| 依赖 | `uv.lock` + Dockerfile | `pip freeze` + `dpkg-query -W` | **镜像 digest** |
| 数据 | schema/fixtures | 表内容 | `CHECKSUM TABLE` / `_count` / `points/count` |
| 配置 | `.env.example` | `.env` | 脱敏 hash |
| 行为 | 契约（steps/errors） | 实际 SSE 流 | 录制夹具 |
| 环境 | compose | `docker ps` | 项目名 + 端口 |

**关键推论**：只有"代码"这一格不同，差异才可归因；否则只能报"存在差异"。

**已知洞**：`.env` 的 `PYTHON_IMAGE` 用的是 tag 不是 digest（tag 会漂）——实验记录里要写 digest。

## D29 录制边界：LLM provider 层 + 双轨

**决定**：验收要求"真实调 LLM"→ 分两轨：

| 轨道 | 生成方式 | 用途 | 可比性 |
|---|---|---|---|
| 演示轨 | 真 LLM（pin 模型版本 / temperature / seed） | 答辩演示 | 单次看效果 |
| 实验轨 | **provider 层录制回放** | 消融实验 | 单次可比 |

**决策逻辑**：随机性影响的是**控制流**（校验失败→correction→多一轮），不只是 SQL 文本；temp=0 只是降低不消除。"录一次、回放 N 次"才能同时满足"真实 LLM"与"可比性"。

**已具备**：`fixtures/sse/` 14 条夹具 + `app/scripts/record_sse.py`（录的是真字节流，模型与 DB 是替身）。缺口：夹具录在 SSE 边界，**不含 prompt/模型原始响应**，无法回答"为什么拒答"——实验轨需录在 provider 边界。

## D30 每页必须有"运行截图"（2026-11-16）

**决定**：练本 9 页每页至少 1 张**运行截图（runshot）**——由脚本真跑该页命令、捕获真实输出、按统一版式渲染成 PNG。第 8 页 2 张（流式中途 / 最终结果），第 9 页 2 张（浏览器成功 / 删掉 nginx 后的报错）。

**备选与否决**
| 方案 | 否决原因 |
|---|---|
| 只保留文字"你应该看到" | 学生不知道"长什么样算对"；文字易读错、易手抄错 |
| 真人手工截屏 | 9 张要人工摆窗口，受字体/分辨率影响，不可复现 |

**决策逻辑**：截图的用途是**判据的视觉锚点**，不是装饰。所以"真"的标准不是"桌面截屏"，而是**内容来自真跑、且能一条命令重跑出来**。

**实现约束**：生成脚本入库（`manual/shots/`）；提示符统一 `$`；不显示用户名/主机名/绝对路径；固定窗宽；端口 3307/8000（与正文一致）。

**何时推翻**：若评审明确要求"必须是真实桌面截图"。

## D32 AOA 只作对照附录，主线仍是 AON（2026-11-17）

**决定**：D31 的「主线用单代号网络图」不变；**新增双代号（AOA/ADM）对照附录**——`manual/flow-aoa.mmd` + `manual/images/flow-aoa.png` + `README.md` 附录一节。用途是教学对照，不进主线、不进答辩主图。

**事实依据**：把十个活动映射成 AOA 后是 **10 个事件（e1–e10）/ 10 条实箭线 / 0 个虚活动**（串并联形状，未撞上「共享同一对起止事件」「只依赖其一」这两种必须加虚活动的形状）。注：10 箭线 + 连通且单终点 ⇒ 事件数必为 10；若强行凑 11 个事件就必须加 1 条虚活动。

**后果**：GLOSSARY 增「事件（事项）」「虚活动」，并把 AOA 条目标为仅作对照附录。

**何时推翻**：看完图决定改主线 → 另开 D33 并同步 README/答辩/GLOSSARY。

## D33 教学用版本快照：对学生隐藏 VCS，快照只读不可覆盖（2026-11-17）

**决定**
1. **11 个边界快照 S0–S10**（S0 = 空起点，S10 = 全部完成）；`A<n>-start` 与 `A<n>-done` 是同一批快照的两个别名（`A<n>-start = S<n>`，`A<n>-done = S<n+1>`）。
2. 学生侧只暴露 6 条命令：`lab status / save / start / done / diff / reset`；**学生不接触 git**。
3. 跳转机制用 **overlay**（`lab` 从只读快照解出文件覆盖工作区），不切分支、不 stash、不产生 detached HEAD。
4. **必须先保存才能跳转**：工作区有未保存改动时 `lab start/done` 拒绝执行，提示先 `lab save <名字>`——把"存档"训练成肌肉记忆。
5. **教学快照禁止被覆盖**：快照只存在于 git 的 `snapshots` 分支/只读缓存（chmod 555 + 读前校验哈希）；学生保存只能写入 `.lab/saves/`，与 `.lab/snapshots/` 物理隔离。
6. **容器/数据库状态纳入回滚（Q4=b）**：`lab start A1/A2` 会重建容器并重新导入 `fixtures/dw.sql`；因属破坏性操作，必须**交互确认或显式 `--yes`**，不允许静默执行。
7. **实现时机（Q5=a）**：验收后再做；当前只把方案写进 README/决策，三天冲刺优先保 A–E 判据。

**为什么不让学生直接见 git**：初版目标是"构建体验 + 心智模型"，git 的 detached HEAD/stash/冲突会抢走教学注意力；"揭开版本控制"留作后续可选页。

**后果**：`lab/` 与学生保存目录进 `.gitignore`；快照内容只覆盖文件，**容器/数据必须由 `lab` 显式重建**。

## D34 封装梯度：前段抽象体验，后段逐层减封装（2026-11-17）

**决定**（用户对开发教材的整体预期）
1. **前 10 页**：细节少、抽象多。目标是**构建项目的体验**与**对项目的心智模型**——每个活动尽量"一条命令完成"（封装足够好）。
2. **后续约 20 页**：逐层打开细节。**每页对某个活动减少一层封装**，让学生多做一步才能完成同样的目标。
3. **永不完全去封装**：最后一层仍保留封装（例如仍用 `lab` 起环境，只让学生手写业务代码）。

**判据**：同一活动在后续页里"学生要敲的命令/写的代码"应比前一页**多一层**，但**不超过三层**（避免变回"从零手搓"）。

**待解决**：现有 10 页（第 0–9 页）是"半开封装"（1–2 页命令、3–9 页手写 app.py），既非第一层也非最后一层，需要重新定位到 Pass 1 / Pass 2。

**修订（2026-11-17，用户纠正）**：难度**不是**"一层层剥掉封装"，而是**同一过程里学生要做的事变多**——L0–L2 的元素可以**混在同一难度段/同一页**内，只是"学生自做的部分"占比上升、`lab` 代劳的部分下降。因此本决策改为"**封装分界线移动模型**"：

| 难度档 | `lab` 代劳 | 学生自做 | 例（A3 最小 HTTP 服务） |
|---|---|---|---|
| 体验版 | 起环境、装依赖、写服务、启动 | 只发 `curl` 看结果 | `lab build A3` + `curl /health` |
| 进阶 1 | 起环境、装依赖 | 自己启动服务、自己 `curl` | `uvicorn …` + `curl` |
| 进阶 2 | 只起环境 | 自己写 9 行代码 + 启动 + 验证 | 现在第 3 页 |
| 高阶 | 起环境（永不代劳的只有环境） | 改契约/配置驱动行为 | 选修 |

**判据**：难度提升 = **学生独立决策点变多**（不是代码行数变多）；同一页允许 L0+L1+L2 混排。

## D35 三段式结构：十个活动 × 三档 = 30 页（2026-11-17）

**决定**
1. 全书按**档**分 Part（Q2=c）：**Part I = Lv0 体验档（10 页，新写）**、**Part II = Lv1 进阶档（现有第 0–9 页，即 A0–A9 各一页）**、**Part III = Lv2 进阶档（10 页，新写）**。
2. 每个活动 A0–A9 在三个 Part 里各出现一次，共 30 页；现有 10 页**整段归入 Lv1**（Q1）。
3. 难度度量：**学生独立决策点数为主**（要自己选端口/路径/参数/结构），命令条数与手写代码行数为辅（Q3）。
4. 每档的"封装分界线"不同但同页可混：Lv0 = `lab` 代劳到"一条命令完成一个活动"；Lv1 = 现有页（命令 + 手写代码）；Lv2 = 再往左移一格（具体待目录草案确定）。
5. **环境永不代劳**（Docker/uv/venv 始终由 `lab`/make 兜底），确保不退回"从零手搓"。

## D41 状态粒度下沉到"能力格"：一格一状态，节点/槽位/结构图全部派生（2026-11-17）

**问题**：D40 把编辑入口放在卡片顶部一个控件上，但**一张卡里有多项能力**（例：L1「人→系统交互」有"接收提问""返回答案"两格），点一次顶部徽章会把两格同时改掉——判定被"打包"，违背"一个能力一个判据"。

**决定**
1. 唯一真源下沉到**矩阵格**：每个"节点 × 能力"格子独立三态 `▢/◧/■`；`—`（不提供）不可编辑。
2. **节点状态由格子派生**：所有可编辑格 ▢ ⇒ 节点 ▢；所有可编辑格 ■ ⇒ 节点 ■；否则 ⇒ 节点 ◧。
3. 槽位状态 = 所属节点状态（A1·A2 同源同步）；结构图块徽章 = 节点状态（只读）。
4. 卡片顶部徽章改为**只读派生**，tooltip 写明"由本卡 N 项能力派生：x■ y◧ z▢"。
5. 计数全部按格重算：行覆盖=节点 ■ 的行数；列覆盖=该列至少一格 ■；跨层边通=两端节点均 ■；槽位 ■=节点 ■ 的槽位数；印章=三条判据全绿。
6. 答案态：所有"提供"格 ■、只读；空白态：所有格 ▢、可点编辑。

**后果**：`data.json` 需为每节点每能力存初始态；`build_explorer.py` 的 DOM 自检要覆盖"改一格 → 节点派生 → 结构图派生 → 计数变化"。

## D42 《建成证明》v2：行=交付物（物料清单），格=检验点（2026-11-18）

## D44 四级 = 四种工程动作（造→换→审→守），L2–L4 是横切系统而非"又一批零件"（2026-11-19）

**决定**
