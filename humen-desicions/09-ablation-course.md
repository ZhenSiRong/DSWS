# 09 · 消融实验式教材重构（2026-11-15）

> 本文记录 2026-11-15 一轮决策的**完整逻辑**：背景、备选、取舍、后果、何时可推翻。
> 对应 `DECISIONS.md` 的 D20–D29。验收窗口：**3 天后**（2026-11-18）。

## 背景（为什么现在要动）

- 现有教材 `dev-book.pdf`（162 页）由 agent 全权重写，**形式完整、可读性差**：对使用者"完全学不了"。
- 交付剩余 **3 天**；使用者愿意全力投入（约 36 小时），无其他人手。
- 评审形式已确认：**要跑、要答辩、要演示最小教学闭环**（不是只交文档）。

## D20 教材重构：主线练本 + 原书降为参考书

**决定**：新写一本主线（9 页起步、可长到 30 页），原书 162 页**一个字不动**，降级为"参考书/查字典"。

**备选**
| 方案 | 优点 | 否决原因 |
|---|---|---|
| A. 在原书上删改 | 只交一份 | 162 页是链式结构，删一节垮三节；写坏了无法回退 |
| B. 原书不动 + 新写练本 ✅ | 风险隔离；两天能成稿 | 交付物变成两册（用"读本+练本"分工解释） |
| C. 只加一本薄手册 | 最省事 | 满足不了"可跟练"的强需求 |

**决策逻辑**：用 3 天改 162 页 = 每页 13 分钟，必然烂尾；而"读本/练本"分工本身就是答辩时的一句话：*这本书告诉你系统长什么样，这本手册让你亲手把它造一遍。*

**后果**：交付两册；`dev-book.pdf` 需在 README 标注"参考书"。

**何时推翻**：若评审明确要求"只能交一份教材"。

## D21 九站构建切法（不是十二步，是九个里程碑）

**决定**：练本以 9 个"能跑的里程碑"组织，每页末尾系统必须**多出一个可验证的新行为**。

| 页 | 造什么 | 页末能看到 |
|---|---|---|
| 1 | 起库 + 建 `fact_order` | `SHOW TABLES` 有它 |
| 2 | 灌 115 行种子 + SELECT | `COUNT(*) = 115` |
| 3 | 最小 HTTP 服务 | `curl /health` → ok |
| 4 | `/api/query` 硬编码 | 固定 JSON |
| 5 | 抽关键词 | `["华北","销售额"]` |
| 6 | 查契约 + 拼 SQL | 打印那条 SELECT |
| 7 | 真执行 | **`41099.5`** |
| 8 | 改成 SSE | 12 条 progress 逐条冒 |
| 9 | 接原版界面（nginx 反代） | 浏览器出结果 |

**决策逻辑**：3 页版虽然"跑得通"，但**像部署不像构建**——`compose up -d` 是别人盖好房子你按开关。放宽到 9 页后，每页都有"自己垒出来的一块"，且前 8 页都不需要界面（用 curl 验证），天然教出"前端只是入口"。

**余地**：若第 8 页（SSE）写不完，把第 9 页（界面）降级为附录——**SSE 比界面更核心**（答辩要演流式）。

**何时推翻**：写到第 7 页时评估剩余时间。

## D22 教学法内核：猜 → 造 → 对账

**决定**：每一页固定四段：**一个预测问题 → 动手造 → "你应该看到"的判据 → 对账（你猜对了吗，差在哪）**。

**备选**：学→做→验（先讲后练）；装→跑→问→验。

**否决原因**：两者都是"先灌后练"，学生仍是被动。**"先猜"零成本，却把"照做"变成"理解"**——预测被打脸的那一刻才是学习发生的时刻（本项目的删 frontend 教学实验已验证：学生猜"系统坏了"，实际主干还活着）。

**后果**：每页必须有一个"错误预测也有价值"的问题；不能只出送分题。

## D23 单页预算（"精细"的可操作定义）

**决定**：每页硬上限——**1 个新代码段（≤40 行）+ ≤3 条命令 + 1 个"你应该看到" + 1 个"猜"的问题 + 1–3 行"必须自己改"的小任务**。

**决策逻辑**：精细 ≠ 命令写得多。检验标准是**每条命令都有对照物**——学生卡住时只需自问"我的输出和书上这行一样吗"。

**后果**：超过 40 行的页要拆；"必须自己改"是防抄的硬钩子。

---

## D24 代码形态：前半整段，后半 diff

**决定**：第 1–5 页给**可整段复制**的代码；第 6 页起逐步改为"在上一步基础上改这几行"。

**决策逻辑**："都不会"的学生第一步是"能不能跑起来"，不是"为什么这么写"。等他有了能跑的基础，再给 diff 才有意义。

## D25 构建式而非部署式（硬规则）

**后果**：`compose.lab-ui.yaml` 这类"一键起全套"只作为**调试用**，不进正文主线。

## D27 worktree 隔离策略（"刀刃"）

**决定**：隔离切在 **代码 / 依赖 / 运行单元** 与 **数据** 之间——前三者每实验一份，**数据默认共享**。

**前提（契约）**：共享数据成立的条件是 ①全链路只读（`dw_reader` 仅 SELECT）②**谁都不跑 `init`**。要写数据（改种子/重建 meta/改 schema）时才必须独立一份。

**事实依据**（本仓库实测）
- worktree 隔离工作文件 + index + HEAD；**共享** `.git/objects` 与 `refs`（`.git/index` 与 `.git/worktrees/<wt>/index` 是两个文件）。
- 两套独立栈（主栈 / lab 栈）数据指纹完全一致：5 张表 checksum 相同、ES 76 docs、Qdrant 98/22。

**后果**：不复制存储；用命名空间（`REBUILD_META_DB` / `REBUILD_ES_INDEX` / collection 名）隔离需要改数据的情形。

**何时推翻**：实验要改数据本身（那时数据就是第二个因子）。

## D28 六格仪表盘（变量 × 仪器）

**决定**：对比实验前必须采集六格身份卡：

| 变量 | 声明 | 现场 | 身份 |
|---|---|---|---|
| 代码 | 分支/提交 | `git status` | commit sha |
| 依赖 | `uv.lock` + Dockerfile | `pip freeze` + `dpkg-query -W` | **镜像 digest** |
| 数据 | schema/fixtures | 表内容 | `CHECKSUM TABLE` / `_count` / `points/count` |
| 配置 | `.env.example` | `.env` | 脱敏 hash |
| 行为 | 契约（steps/errors） | 实际 SSE 流 | 录制夹具 |
| 环境 | compose | `docker ps` | 项目名 + 端口 |

**关键推论**：只有"代码"这一格不同，差异才可归因；否则只能报"存在差异"。

**已知洞**：`.env` 的 `PYTHON_IMAGE` 用的是 tag 不是 digest（tag 会漂）——实验记录里要写 digest。

## D29 录制边界：LLM provider 层 + 双轨

**决定**：验收要求"真实调 LLM"→ 分两轨：

| 轨道 | 生成方式 | 用途 | 可比性 |
|---|---|---|---|
| 演示轨 | 真 LLM（pin 模型版本 / temperature / seed） | 答辩演示 | 单次看效果 |
| 实验轨 | **provider 层录制回放** | 消融实验 | 单次可比 |

**决策逻辑**：随机性影响的是**控制流**（校验失败→correction→多一轮），不只是 SQL 文本；temp=0 只是降低不消除。"录一次、回放 N 次"才能同时满足"真实 LLM"与"可比性"。

**已具备**：`fixtures/sse/` 14 条夹具 + `app/scripts/record_sse.py`（录的是真字节流，模型与 DB 是替身）。缺口：夹具录在 SSE 边界，**不含 prompt/模型原始响应**，无法回答"为什么拒答"——实验轨需录在 provider 边界。

## D30 每页必须有"运行截图"（2026-11-16）

**决定**：练本 9 页每页至少 1 张**运行截图（runshot）**——由脚本真跑该页命令、捕获真实输出、按统一版式渲染成 PNG。第 8 页 2 张（流式中途 / 最终结果），第 9 页 2 张（浏览器成功 / 删掉 nginx 后的报错）。

**备选与否决**
| 方案 | 否决原因 |
|---|---|
| 只保留文字"你应该看到" | 学生不知道"长什么样算对"；文字易读错、易手抄错 |
| 真人手工截屏 | 9 张要人工摆窗口，受字体/分辨率影响，不可复现 |
| 手绘/PS 截图 | 不可复现，答辩被质疑无法自证 |

**决策逻辑**：截图的用途是**判据的视觉锚点**，不是装饰。所以"真"的标准不是"桌面截屏"，而是**内容来自真跑、且能一条命令重跑出来**。

**实现约束**：生成脚本入库（`manual/shots/`）；提示符统一 `$`；不显示用户名/主机名/绝对路径；固定窗宽；端口 3307/8000（与正文一致）。

**何时推翻**：若评审明确要求"必须是真实桌面截图"。
