# 图表可理解性优化计划（2026-11-09 确认版）

> 类型：开发（过程）文档。设计产物落在 `design/`，本文只记录做法、判据与排期。

## 1. 目标

设计文档与开发教材是两份文档：本文的优化对象是 **design-doc.pdf 里的 32 张技术图**（图 3-0 属开发教材，另算）。
不是“更漂亮”，而是三个问题都能答出来：

1. 这张图回答什么问题？
2. 关键路径是哪 3 个节点？
3. 如果某一步失败，会发生什么？

## 4. 判据（Q2）

每张图过三问，答对 2/3 才算过：

1. 这张图回答什么问题？
2. 关键路径是哪 3 个节点？
3. 某一步失败会发生什么？

执行方式：

- **盲测**：把图 + 图注交给便宜视觉模型，不让它看 `.md` 答案；与 `reading-paths.yaml` 的期望答案比对。
- **抽检**：随机 3 张，让 `hy3 --effort low` 的学生 agent 只看图复述；必须命中“一句话”。
- **版面**：图与图注同页、不溢出、文字不重叠。

## 5. 技术做法（Q3/Q4）

### A 类：读图带

后处理脚本 `design/scripts/add_reading_band.py`：

- 读取 SVG，增高 `height/viewBox`，把原内容整体下移；
- 顶部加一条浅色带：`这张图回答：…` + `读图 1→2→3：…` + `失败：…`；
- 不改原图的节点与边，风险最低。

**顺序**：`render_all.py` → `add_reading_band.py` → 构建 PDF。
否则重新渲染会覆盖读图带。

### B 类：类比横幅

在 `.md` 的“一句话”后加一句生活化类比，并同步到书稿图注；不生成新图。

### B1 类：6 张漫画

- 走现有管线：content JSON → SVG/混合图 → 门禁 → hy4free 复核；
- 只使用 Seedream Lite（免费额度），Pro 0 张；
- 文字必须外置，不允许烧进栅格。

## 8. 风险与回退

| 风险 | 缓解 |
|---|---|
| 读图带增高导致 PDF 溢出 | 先做 3 张样张，检查分页；必要时带高从 56px 降到 44px |

| 32 张一天做不完 | P0 优先；P1 只审计 |
